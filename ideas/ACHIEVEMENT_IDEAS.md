## Design Notes

### Achievement Philosophy

1. **Layered Discovery**: Players should naturally unlock simple achievements first (First Victory, Tactical Retreat), then discover medium-tier ones through experimentation, and finally hunt the bizarre ones intentionally.

2. **No Grind Gates**: Even cumulative achievements should be set at numbers players naturally hit through normal play. The journey is the reward — the achievement is just the receipt.

3. **Humor Over Seriousness**: This is a game where you stand on a wall and fire Magic Missiles at pixel armies. The tone should match. Achievement descriptions are an opportunity for jokes.

4. **Hidden Achievements Drive Exploration**: The "???" achievements encourage players to try weird things. "What happens if I put a wall on the King?" becomes a question worth answering.

5. **Browser-Specific Achievements**: These acknowledge the medium. Players know they're in a browser tab. Leaning into that creates a unique identity other games don't have.

6. **Failure is Content**: Defeat achievements normalize losing and turn bad outcomes into progress. Getting "Accidental Regicide" after killing your own King softens the sting.

7. **Cross-Archetype Rewards**: Achievements that require different wizard types push players to try all three playstyles, increasing replayability.

### Implementation Considerations

- **Tracking**: Most achievements need counters or flags that persist in the save file (kills, spells cast, time played, etc.)
- **Browser APIs**: Time-of-day achievements need `js_sys::Date`, window focus/blur events need `web_sys` listeners
- **Hidden achievements**: Show "???" with no description in the progress screen until unlocked, then reveal the full name and description
- **Popup timing**: Multiple achievements unlocked simultaneously should queue, not stack
- **Save migration**: New achievement fields need backwards-compatible defaults in the save file deserializer
